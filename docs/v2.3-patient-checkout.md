# v2.3 Patient Checkout

## Delivered
- PostgreSQL-backed payment intent persistence.
- PostgreSQL-backed webhook event idempotency.
- Patient-authorized payment lookup and payment history APIs.
- Appointment-to-payment flow using the consultation price stored on the verified doctor record.
- Secure provider-hosted checkout handoff boundary.
- Premium responsive Patient checkout screen.
- Patient payment history screen with retry/continue-payment action.

## Patient journey
1. Patient selects a verified specialist and availability slot.
2. Appointment is reserved.
3. CareBridge sends the patient to `/checkout/:appointmentId`.
4. Server creates or returns an idempotent payment intent.
5. Patient is handed to provider-hosted checkout.
6. Signed webhook changes server-side payment status.
7. Patient dashboard/payment history reads the authoritative server status.

## Safety
- No PAN/CVV/card data is accepted by CareBridge.
- Payment creation requires an authenticated patient and patient-owned appointment.
- Idempotency prevents accidental duplicate payment creation.
- Webhook event IDs are persisted so duplicate deliveries can be ignored.
- Development uses the synthetic payment provider only.

## Local database
Apply the Prisma SQL migration before exercising the persisted payment endpoints. The API also contains a development-safe table bootstrap so the local flow can self-heal when the tables are absent; production deployments must use managed migrations instead.
