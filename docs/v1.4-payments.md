# v1.4 Payments

## Scope
- Consultation price and currency presentation
- Payment-intent adapter
- Checkout state machine
- Provider webhook boundary
- Success/failure/pending states
- Cancellation and refund policy hooks
- Receipt metadata
- Payment audit events

## Security
- Never store card numbers or CVV.
- Provider secrets remain server-side.
- Verify webhook signatures.
- Treat payment status as server-authoritative.
- Use idempotency keys for payment creation and webhook processing.

## Dependency
Starts after v1.3 video session architecture is stable. Production payment provider selection requires legal, tax, geographic and PCI review.
