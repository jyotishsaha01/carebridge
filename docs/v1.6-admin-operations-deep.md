# v1.6 Admin Operations — Detailed Build

## Goal
Provide a controlled operations console without exposing unrestricted clinical data.

## Deliverables
- Operations dashboard
- Patient search with minimal identifying fields
- Doctor verification queue
- Appointment operations
- Payment/refund operations boundary
- Support case workflow
- Audit log viewer
- Configuration management
- Role/permission matrix

## API contracts
- GET /v1/admin/overview
- GET /v1/admin/doctors/pending
- PATCH /v1/admin/doctors/:id/verification
- GET /v1/admin/appointments
- PATCH /v1/admin/appointments/:id/status
- GET /v1/admin/audit-events

## Security
Require ADMIN role on every endpoint. Apply least privilege and field minimization. Sensitive clinical content should not be exposed to operations users unless an explicitly authorized workflow requires it. Record actor, action, target, timestamp and request correlation ID for administrative mutations.

## UI
Responsive command center with KPI cards, queues, filters, detail drawers, confirmation dialogs, audit timeline and clear destructive-action warnings.

## Tests
- Non-admin rejected.
- Admin can view operational queues.
- Verification mutations audited.
- Destructive actions require explicit confirmation.
- Pagination/filter parameters validated server-side.
