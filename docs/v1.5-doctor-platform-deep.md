# v1.5 Doctor Platform — Detailed Build

## Goal
Turn the Doctor experience into a secure clinical workspace connected to appointments and patient intake.

## Deliverables
- Doctor dashboard
- Today's appointment queue
- Appointment detail
- Patient intake summary
- Consultation notes draft/final state
- Prescription draft/final state
- Follow-up plan
- Doctor availability model
- Appointment status transitions
- Patient-safe data minimization
- Audit events for clinical actions

## API contracts
- GET /v1/doctor/dashboard
- GET /v1/doctor/appointments
- GET /v1/doctor/appointments/:id
- PATCH /v1/doctor/appointments/:id/status
- GET /v1/doctor/appointments/:id/intake
- POST /v1/doctor/appointments/:id/notes
- POST /v1/doctor/appointments/:id/prescription
- POST /v1/doctor/appointments/:id/follow-up

## Security
Every endpoint must verify authenticated DOCTOR role and appointment assignment. Clinical data must never be accepted solely on a patientId supplied by the browser. All write operations require server-side ownership checks and audit events.

## UI
Build a premium responsive workspace with queue filters, patient summary cards, appointment timeline, clinical note editor, prescription composer, follow-up composer, autosave indicators, unsaved-change protection, and reduced-motion support.

## Test requirements
- Unauthorized patient cannot access doctor endpoints.
- Doctor cannot access another doctor's appointment.
- Clinical writes require assigned doctor.
- Appointment status transitions reject invalid states.
- Empty/invalid clinical input returns typed validation errors.
