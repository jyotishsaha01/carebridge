# v2.2 Payments + Webhooks

## Delivered
- Provider-neutral payment intent contract.
- Local/test fake provider with no card-data handling.
- Explicit payment lifecycle states.
- Idempotency key on payment creation.
- Webhook signature boundary.
- Duplicate webhook protection by event ID.
- Server-authoritative payment status model.

## Patient flow
1. Patient confirms consultation price.
2. CareBridge creates a payment intent with an idempotency key.
3. Patient completes provider-hosted checkout.
4. Provider sends a signed webhook.
5. CareBridge verifies the signature and applies the event once.
6. Appointment/payment UI reads server state rather than trusting the browser.

## Production gates
- Select a PCI-compliant payment provider for the target geography.
- Store provider credentials only in production secret management.
- Persist payment intents and processed webhook IDs in PostgreSQL.
- Add provider-specific signature verification and reconciliation jobs.
- Define cancellation/refund policy and tax treatment with legal/accounting review.
- Never collect or store PAN/CVV in CareBridge.
