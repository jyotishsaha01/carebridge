# v2.1 Account Security

## Implemented
- Patient email verification state and one-time verification tokens.
- One-time password reset tokens with short expiry.
- Password reset revokes existing sessions.
- Authenticated users can list and revoke their own sessions.
- Sensitive authentication events are written to the audit log with request context.
- Production email delivery remains behind a provider-neutral adapter and fails closed until a real provider is configured.

## Local/test behavior
With `ALLOW_DEMO_AUTH=true` outside production, signup and password-reset responses may include a development token so the flows can be exercised locally. Production never returns these tokens.

## Production gate
Before production launch, configure a reviewed transactional email provider, enforce email verification, add abuse/rate limiting, configure secret management/key rotation, and complete privacy/security/legal review. No real patient data belongs in development or CI.
