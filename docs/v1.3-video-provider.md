# CareBridge v1.3 — Video Provider Integration

## Goal
Introduce a provider-neutral video session layer for patient/doctor consultations without exposing provider credentials to browsers.

## Scope
- Provider adapter interface
- Server-side session provisioning contract
- Appointment ownership and consultation-window checks
- Waiting-room readiness state
- Join-token boundary (server generated only)
- Provider-neutral room/session identifiers
- Audit events for session created/joined/ended
- Failure states: NOT_PROVISIONED, NOT_STARTED, EXPIRED, UNAVAILABLE
- Patient and Doctor UI contracts for pre-call and active consultation

## Security requirements
- Never return API keys or provider secrets to clients.
- Never persist raw provider tokens in PostgreSQL.
- Join tokens must be short-lived and scoped to one appointment and role.
- Verify authenticated user, appointment ownership, status, and join window on every token request.
- Do not record audio/video by default.
- Production provider credentials must come from server-side secret management.

## Provider adapter

```ts
interface VideoProvider {
  createSession(input: { appointmentId: string }): Promise<{ providerSessionId: string }>;
  createParticipantToken(input: { providerSessionId: string; userId: string; role: "PATIENT" | "DOCTOR" }): Promise<{ token: string; expiresAt: string }>;
  endSession(input: { providerSessionId: string }): Promise<void>;
}
```

The initial implementation remains provider-neutral. A real vendor is selected and configured only after compliance, BAA/data-processing, geographic availability, recording policy, and pricing review.

## Acceptance criteria
- Patient can only request a session for their own eligible appointment.
- Doctor can only join appointments assigned to them.
- Tokens expire automatically.
- No provider secret reaches browser JavaScript.
- Every session lifecycle event is auditable.
- Local/test environment uses a deterministic fake provider with synthetic data only.
